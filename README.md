# Sales Assistant MVP

نسخه آزمایشی دستیار فروش با FastAPI و SQLite. صفحه وب، اینستاگرام و تلگرام همگی از یک موتور مکالمه برای قیمت، پرسش‌های متداول، ثبت شماره، سفارش و ارجاع به اپراتور استفاده می‌کنند.

## Database migrations

Alembic is the production schema history. Validate every revision before use:

    python -m tools.migration_policy
    python -m pytest tests/test_alembic.py tests/test_migration_policy.py -v

Create the next sequential revision, review all autogenerated operations, and
then apply it:

    alembic revision --autogenerate --rev-id 0002_short_snake_case -m "short description"
    alembic upgrade head

Use `alembic upgrade head` for a new database. Use `alembic stamp
0001_baseline_schema` only to onboard an independently verified existing schema;
never stamp an empty database. Full naming, destructive-operation, downgrade,
multi-tenant, recovery, and PostgreSQL guidance is in the
[production migration policy](docs/architecture/database-migrations.md).

## Seed data

Seed execution is explicit and never runs during application startup. List the
registered seeds, dry-run them against an already migrated database, then execute
with an explicit profile and database selection:

    python -m tools.seed_data --list
    python -m tools.seed_data --profile development --dry-run --database-url sqlite:///./local.db
    python -m tools.seed_data --profile production --database-url YOUR_DATABASE_URL
    python -m tools.seed_data --profile production --tenant store-slug --database-url YOUR_DATABASE_URL

The production profile accepts only explicitly production-safe seeds. Tenant
seeds require a resolved tenant slug, re-runs are idempotent, and database URLs
are not printed. See the [production seed-data framework](docs/architecture/seed-data.md)
for ownership, audit, recovery, concurrency, and secrets rules.

## راه‌اندازی در Windows PowerShell

```powershell
.\.venv\Scripts\Activate.ps1
python -m uvicorn app.main:app --reload
```

سپس این آدرس‌ها در دسترس‌اند:

- صفحه نمایشی چت: `http://127.0.0.1:8000/demo`
- سلامت سرویس: `http://127.0.0.1:8000/health`
- فهرست محصولات: `http://127.0.0.1:8000/products`
- فهرست سؤالات متداول: `http://127.0.0.1:8000/faqs`
- سرنخ‌های دارای شماره تماس: `http://127.0.0.1:8000/leads`
- سفارش‌های ثبت‌شده: `http://127.0.0.1:8000/orders`
- مستندات و محیط تست: `http://127.0.0.1:8000/docs`

در صفحه مستندات، مسیر `POST /chat` را باز کنید و با این ورودی امتحان کنید:

```json
{
  "instagram_user_id": "test-user-1",
  "message": "قیمت آیفون ۱۵ چنده؟",
  "customer_name": "مشتری آزمایشی"
}
```

پیام‌های نمونه دیگر:

- `چه محصولاتی دارید؟`
- `سامسونگ A55 موجوده؟`
- `قیمت قاب آیفون چنده؟`
- `شرایط ارسال چیه؟`
- `شماره من ۰۹۱۲۱۲۳۴۵۶۷ است`
- `همین‌جا سفارش من را ثبت کن`
- `می‌خواهم با اپراتور صحبت کنم`
- `salam, gheymat iphone 15 chande?`
- `haminja sefaresh mano sabt kon`
- `ba operator sohbat konam`

ورودی‌های رایج فینگلیش برای قیمت، محصول، سفارش، اپراتور، ارسال، گارانتی، تخفیف، اقساط، رجیستری، مرجوعی و تشکر به عبارت استاندارد فارسی تبدیل می‌شوند.

صفحه دمو دکمه ثابت «ارتباط با اپراتور» و بخش جداگانه سفارش‌ها دارد. سفارش آزمایشی فقط پس از انتخاب محصول و ثبت شماره تماس ایجاد می‌شود و تا زمان پیگیری اپراتور در وضعیت `pending` باقی می‌ماند.

```powershell

```

در اولین اجرای برنامه، محصولات و پرسش‌های فرضی به‌صورت خودکار و بدون ایجاد رکورد تکراری وارد SQLite می‌شوند. مقادیر `.env` محرمانه‌اند و نباید وارد Git شوند.

## اتصال تلگرام برای تست واقعی

تلگرام برای تست روی همین لپ‌تاپ از روش Polling استفاده می‌کند؛ بنابراین در این مرحله به دامنه یا آدرس عمومی HTTPS نیاز نداریم.

1. در تلگرام فقط ربات رسمی `@BotFather` را باز کنید، دستور `/newbot` را بفرستید و نام و نام کاربری ربات را تعیین کنید.
2. توکن دریافتی را در چت، Git یا تصویر صفحه منتشر نکنید.
3. در PowerShell داخل پوشه پروژه این فایل را اجرا کنید. توکن هنگام ورود روی صفحه نمایش داده نمی‌شود:

```powershell
.\scripts\configure_telegram.ps1
```

4. برنامه FastAPI را یک‌بار متوقف و دوباره اجرا کنید.
5. در یک پنجره PowerShell جداگانه، دریافت پیام‌های تلگرام را شروع کنید:

```powershell
.\scripts\start_telegram.ps1
```

6. ربات خود را در تلگرام باز کنید، دکمه `Start` را بزنید و یکی از این پیام‌ها را بفرستید:

- `gheymat iphone 15 chande?`
- `محصولات موجود`
- `ثبت سفارش`
- `ارتباط با اپراتور`

ربات یک صفحه‌کلید دائمی با گزینه‌های «محصولات موجود»، «ثبت سفارش» و «ارتباط با اپراتور» نشان می‌دهد. مسیر `GET /telegram/status` فقط وضعیت آماده‌بودن اتصال را نشان می‌دهد و هیچ توکن یا راز امنیتی را برنمی‌گرداند.

برای استقرار نهایی می‌توان Polling را با `POST /webhooks/telegram` جایگزین کرد. Webhook فقط درخواست‌هایی را می‌پذیرد که هدر امنیتی `X-Telegram-Bot-Api-Secret-Token` درست داشته باشند. Polling و Webhook نباید هم‌زمان فعال باشند.

## اتصال به Instagram API

برای ذخیرهٔ امن اطلاعات Meta، برنامه را فقط روی لپ‌تاپ اجرا کنید و صفحهٔ محلی زیر را باز کنید:

`http://127.0.0.1:8000/instagram/setup`

این صفحه فقط در محیط `development` و فقط از آدرس loopback باز می‌شود. Access Token و App Secret در پاسخ، HTML، وضعیت سیستم یا لاگ نمایش داده نمی‌شوند و هیچ درخواست آزمایشی به Meta ارسال نمی‌شود. فایل `.env` به‌صورت اتمیک به‌روزرسانی می‌شود و سایر تنظیمات آن حفظ می‌شوند. Webhook Verify Token با Web Crypto در خود مرورگر ساخته می‌شود و تا زمان ذخیره قابل مشاهده و کپی است تا همان مقدار را عیناً در پنل Meta وارد کنید. سرور آن را در پاسخ برنمی‌گرداند؛ اگر این فیلد عمداً خالی ارسال شود، سرور فقط به‌عنوان پشتیبان یک مقدار امن می‌سازد و ذخیره می‌کند.

این پروژه از مسیر «Instagram API with Instagram Login» استفاده می‌کند. تا وقتی اطلاعات Meta وارد نشده‌اند، Webhook در حالت شبیه‌سازی است و هیچ پیام خارجی ارسال نمی‌شود.

تنظیمات لازم در فایل `.env`:

```dotenv
META_VERIFY_TOKEN=یک-عبارت-تصادفی-طولانی
META_APP_SECRET=مقدار-App-Secret
META_ACCESS_TOKEN=توکن-حساب-حرفه‌ای-اینستاگرام
META_IG_USER_ID=شناسه-حساب-حرفه‌ای
META_API_VERSION=v24.0
META_SEND_ENABLED=true
META_SIGNATURE_REQUIRED=true
```

مسیرهای اتصال:

- وضعیت امن تنظیمات: `GET /instagram/status`
- تأیید Webhook توسط Meta: `GET /webhooks/instagram`
- دریافت رویداد پیام: `POST /webhooks/instagram`

برای اتصال واقعی باید برنامه روی یک آدرس عمومی HTTPS در دسترس باشد. Callback URL در Meta باید به شکل `https://YOUR-DOMAIN/webhooks/instagram` ثبت شود و فیلدهای `messages` و `messaging_postbacks` برای حساب حرفه‌ای Subscribe شوند. پیام‌های تکراری Meta با شناسه `mid` دوباره پردازش نمی‌شوند و امضای `X-Hub-Signature-256` نیز بررسی می‌شود.

## اتصال ManyChat به موتور فروش

در Dynamic Block منی‌چت، درخواست زیر را با متد `POST` به یک آدرس عمومی HTTPS بفرستید:

`https://YOUR-DOMAIN/integrations/manychat/instagram`

یک مقدار تصادفی و طولانی برای `MANYCHAT_DYNAMIC_BLOCK_SECRET` در فایل `.env` قرار دهید و همان مقدار را فقط در هدر سفارشی زیر وارد کنید؛ این راز را در بدنه درخواست یا Git ذخیره نکنید:

```text
Authorization: Bearer YOUR_SECRET
```

بدنه مورد انتظار:

```json
{
  "contact": {
    "id": 13245647,
    "page_id": 234564657,
    "first_name": "Customer",
    "last_name": "Lastname",
    "name": "Customer Lastname",
    "last_input_text": "gheymat iphone 15 chande?",
    "last_interaction": "2026-07-11T10:30:00+00:00",
    "live_chat_url": "https://manychat.com/example"
  }
}
```

پاسخ با قالب Dynamic Block نسخه `v2` و نوع `instagram` برگردانده می‌شود. درخواست تکراری همان پاسخ ذخیره‌شده را می‌گیرد و مکالمه یا سفارش را دوباره ایجاد نمی‌کند.

## کنسول مدیر و استودیوی محتوای محصول

کنسول محلی مدیر در `http://127.0.0.1:8000/admin` قرار دارد. مدیر می‌تواند محصولات، قیمت، موجودی، عبارت‌های مشابه و پاسخ‌های فروشگاه را وارد کند؛ پیشنهادهای سیستم را بررسی کند و سپس نسخه تأییدشده را برای ایجنت فعال کند.

مرحله «استودیوی محتوا» این امکانات را دارد:

- افزودن چند تصویر برای هر محصول و انتخاب تصویر اصلی هر پست؛
- آماده‌سازی عکس در مرورگر به JPEG مربعی و حذف اطلاعات جانبی فایل؛
- تولید متن پست، هشتگ، توضیح تصویر و عبارت‌های قابل‌تشخیص در دایرکت؛
- ویرایش و تأیید جداگانه مدیر پیش از هر انتشار؛
- ثبت شناسه پست منتشرشده در `InstagramMediaProduct` تا کامنت «قیمت» به همان محصول متصل شود.

انتشار واقعی پست به‌صورت پیش‌فرض خاموش است. برای فعال‌کردن آن، علاوه بر مجوز `instagram_business_content_publish` و توکن تازه، یک میزبان دائمی HTTPS برای تصاویر لازم است:

```dotenv
META_CONTENT_PUBLISH_ENABLED=true
PUBLIC_MEDIA_BASE_URL=https://media.example.com
MEDIA_SIGNING_SECRET=یک-راز-تصادفی-طولانی
MEDIA_STORAGE_ROOT=./private_media
```

## مدل SaaS ماژولار و ساب‌دامین فروشگاه‌ها

در کنسول محلی `/admin` دکمه «ماژول‌ها و قیمت‌ها» این امکانات را فراهم می‌کند:

- ساخت رکورد فروشگاه و رزرو یک slug برای ساب‌دامین؛
- قیمت مستقل ماهانه و راه‌اندازی برای هر ماژول، با ذخیره‌سازی به ریال و نمایش به تومان؛
- فعال، آزمایشی، غیرفعال یا متوقف‌کردن هر ماژول برای هر فروشگاه؛
- کنترل وابستگی ماژول‌ها؛ برای نمونه «کامنت به دایرکت» بدون هسته دستیار فروش فعال نمی‌شود؛
- جلوگیری سمت سرور از اجرای قابلیت خاموش؛ خاموش‌کردن `comments_to_dm` هیچ دایرکت یا پاسخ عمومی ارسال نمی‌کند.

قیمت‌های فعلی پیشنهادی و قابل‌ویرایش‌اند و درگاه پرداخت یا صدور صورتحساب خودکار هنوز متصل نشده است. برای شکل ساب‌دامین‌ها تنظیمات زیر در نظر گرفته شده‌اند:

```dotenv
TENANT_BASE_DOMAIN=agent.example.com
TENANT_URL_SCHEME=https
```

با این تنظیم، فروشگاهی با slug برابر `aftab` آدرس `aftab.agent.example.com` می‌گیرد. در محیط توسعه، نمونه محلی آن `aftab.localhost:8000` است.

این بخش فعلاً پایه محصول‌سازی و قیمت‌گذاری است، نه استقرار چندمشتری نهایی. پیش از ارائه عمومی باید احراز هویت مدیران، جداسازی کامل داده‌های هر فروشگاه، توکن رمزنگاری‌شده Meta برای هر فروشگاه، wildcard DNS/TLS و صورتحساب پیاده‌سازی شوند. به همین دلیل `/admin` همچنان عمداً فقط از خود لپ‌تاپ باز می‌شود.

تونل موقت برای Webhook مناسب است، اما برای میزبانی دائمی تصاویر پست توصیه نمی‌شود. فایل‌های تصویری داخل `private_media/` خصوصی می‌مانند و فقط با لینک امضاشده و زمان‌دار برای دریافت Meta قابل دسترسی هستند.
